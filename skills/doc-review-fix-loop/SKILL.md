## Instructions

### そもそもこのスキルは何か

[[doc-review-fix]]（ドキュメントを1回レビューして直すスキル）を、直すべき問題が出なくなるまで繰り返すスキルです。このスキルの仕事は「繰り返す・進み具合を見せる・最後にまとめる」の3つだけで、レビューと修正の中身は doc-review-fix が行います。

この手順書で使う言葉:

- **周（イテレーション）**: doc-review-fix を1回実行すること
- **critical・major・minor**: 指摘の深刻度。critical＝読み手が目的を果たせない／major＝果たせるが手間が大きく増える／minor＝読みやすさの改善余地
- **要確認で残置**: 元資料に無い情報が要るため、作らずに「要確認」と書いて残した指摘
- **収束（CONVERGED）**: その周で、要確認で残したもの以外の critical・major が0件だった状態

### なぜ繰り返すのか

- **直した箇所が、新しい問題を生むことがある。** 直した本人の見直しでは気づけないので、次の周で新しいレビュアーに読ませて確かめる。
- **終わりを数で決める。** 1周ごとに、要確認で残したもの以外の critical・major を数え、0件になったら終わる。最大回数（既定3周）に達したら、収束していなくても打ち切る。
- 判断の基準は「読み手が効率よく目的を達成できるか」。

### パラメータ

| 引数 | 説明 | デフォルト |
|------|------|-----------|
| 1 | 対象ファイル | 直近に作成した成果物。**特定できない場合は推測せず、ユーザーに確認する** |
| 2 | 最大イテレーション数 | 3。短い文書（目安50行未満）なら 1〜2 に下げてよい（下げたら着手前に一言伝える） |
| 3 | 読み手像「誰に・何を・何のために」 | ドキュメントから読み取る／推定 |

例: `/doc-review-fix-loop docs/manual.md 5 "新人エンジニアに、環境構築を、自力で完了してもらう"`

### 進み具合の表示（必須）

1周に数分かかるので、黙らない。次の4回、短文で出す。

1. 着手前: 「doc-review-fix-loop 開始: <ファイル> を最大N周（1周あたりサブエージェント3〜5体、数分×N が目安）」
2. 各周の開始時: 「Iter K/N 開始」
3. 各周の完了時: 「Iter K/N 完了: critical=x major=y minor=z, 判定=CONVERGED/NOT_CONVERGED」
4. 完了時: 最終レポート

---

### 実行手順

周回数 K は 1 から数える。結果ファイルのパスは最初に1つ決め、全周で使い回す（既定: 作業用の一時フォルダの `doc-review-fix-result-<対象ファイル名>.md`）。

#### 0. 前回の結果ファイルを消す

古い結果を読んで誤判定しないよう、各周の始めに消す。

```
rm -f <結果ファイルパス>
```

#### 1. doc-review-fix を実行する

- **1周目**: Skill ツールで [[doc-review-fix]] を呼ぶ（対象ファイル・読み手像・結果ファイルパスを渡す）。
- **2周目以降**: 呼び直さず、1周目で読み込んだ手順（Phase 1〜5）をそのまま実行する。手順が文脈に見当たらなくなっていたら、その周では呼び直す。
- Skill ツールで呼べない環境では、doc-review-fix の SKILL.md を Read して、その手順を実行する。

#### 2. 結果ファイルを読む

ファイルが無い、または `対応サマリ` 表と `収束判定` 節が無ければ、この周は NOT_CONVERGED とする。

#### 3. この周の判定を決める

対応サマリから次の数を出す。

> **残すもの以外の検出数** ＝（critical と major の「検出」）−（critical と major の「要確認で残置」）

| 条件 | 判定 |
|------|------|
| 残すもの以外の検出数 = 0 | **CONVERGED**（要確認で残したものがあっても、本文に明記してあればよい） |
| 残すもの以外の検出数 ≥ 1 | **NOT_CONVERGED** |
| 結果ファイルが無い・形式が崩れている | **NOT_CONVERGED** |

doc-review-fix の結果ファイルが CONVERGED と書いていても、上の数が1以上なら NOT_CONVERGED とする。

#### 4. この周の1行を記録する

`Iter K | critical | major | minor | 判定` を記録する（最終レポートの表にそのまま使う）。終了するかどうかは、この記録を済ませてから手順5で決める。

#### 5. 続けるか終えるかを決める

- CONVERGED → 終了して最終レポートへ。
- NOT_CONVERGED で K < N → K を1増やして手順0へ。
- NOT_CONVERGED で K = N → 打ち切って最終レポートへ。

---

### 最終レポート

```
# doc-review-fix-loop 結果: <ファイル>

| Iter | critical | major | minor | 結果          |
| ---- | -------- | ----- | ----- | ------------- |
| 1    | 2        | 3     | 4     | NOT_CONVERGED |
| 2    | 0        | 0     | 1     | CONVERGED     |

**最終結果: CONVERGED**（または NOT_CONVERGED: 最大N周で打ち切り）

## 収束しなかった経緯（打ち切った場合のみ）
- 最後の周で見つかり、修正したが再確認していない critical X件 / major Y件。内容は最後の結果ファイルから写す
- 最後の結果ファイルが無い・崩れていた場合は、その旨

## 要確認で残した不足（あれば）
- <何が足りないか / 誰に確認すべきか>

（最後の周で minor を修正していたら）最終パスの minor 修正 n 件は再レビュー未実施
```

---

### 補足

- **同じ箇所で指摘が往復したら止める**: 同じ箇所に逆向きの指摘が2周続けて出たら（例: 否定形を肯定形に直す ↔ 元に戻す）、3回目は直さず「要確認」にしてユーザーに委ねる。
- **minor は判定に使わない**: minor が残ったまま CONVERGED で終わるのは正常。
- **もう1周回らない周**: 要確認として残しただけの周や、minor だけを直した周では、次の周は回らない。
- **2周目以降に Skill を呼び直さない理由**: 呼ぶたびに同じ手順書が文脈に積み重なり、文脈を圧迫するため。
- **Agent でラップせず Skill を直接呼ぶ理由**: レビューは doc-review-fix の中で別のサブエージェントが行うので、文脈は十分分かれている。ラップしても起動の手間が増えるだけだった（このスキル群での試行による判断）。
- **最後の結果ファイルは消さない**: 手順0で消すのは各周の始めだけなので、最後の周の結果は残る。最終レポートはここから写す。
- **サブエージェントを起動できない環境**: doc-review-fix が自己レビューに切り替える（その旨が結果ファイルに書かれる）。ループはそのまま回せる。
- このループは [[clear-document-writing]] の Step 6 の実体。
